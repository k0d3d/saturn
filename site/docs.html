Notes that know
how they connect.

Saturn keeps your day in plain files. Tasks, notes and events live in a local JSON workspace, a Markdown mirror lives in Git, and a small SQLite graph remembers how everything relates. Nothing leaves the machine.

Notes

There are two kinds of note. The daily note is a date-keyed page for quick capture — the Notepad card saves it after a short pause. The library holds titled, tagged, dated notes that can be pinned, archived and searched. Several library notes can share the same date; a date is a relationship, not a unique key.

In the Markdown vault these become daily/YYYY-MM-DD.md and notes/YYYY-MM-DD-title-id.md. Each file carries JSON front matter and a plain Markdown body. Editing the files and running saturn vault sync is a supported way to write notes; conflicts are local-first and recorded in conflicts.md.

Linking notes to tasks

Three kinds of connection are recognised in note and task bodies:

  • [[Project X]] — a wiki link. It resolves to a unique note or task title, or to an exact key such as [[note:abc123]].
  • @Project X — a mention. It resolves by unique, case-insensitive title; @task:abc123 is exact. Long prose is fine — Saturn matches the longest unique title prefix. Ambiguous names create no edge rather than guessing.
  • #work tags — each tag is a node, so co-tagged items are two hops apart. Tags are edited in the note's tag field, not in the body.

Each connection becomes an edge in the graph: references, mentions and tagged respectively. In a later pass the editor will offer an @ autocomplete popup and show detected links as chips.

The knowledge graph

The graph lives at ~/.local/share/saturn/graph.sqlite. It is authoritative for relationships: deleting an item from the workspace marks its node stale but does not silently delete its edges. Use saturn graph forget <key> for an intentional removal, and saturn graph backup to snapshot the database.

Nodes use qualified keys:

task:abc123      note:abc123      daily:2026-11-25
event:abc123     tag:work

Every command prints JSON and works with or without the desktop shell:

saturn graph status
saturn graph neighbors task:abc123 2
saturn graph backlinks note:abc123
saturn graph path task:abc123 note:xyz789
saturn graph link task:abc123 supports note:xyz789 "decision behind this"
saturn graph unlink task:abc123 supports note:xyz789
saturn graph list nodes
saturn graph backup

Wiki, mention and tag edges are regenerated from workspace content on every graph command. Agent-created edges are preserved. Relations are lowercase words, digits, hyphens and underscores — names like supports, follows-up or derived-from make the graph easier to read later.

For AI agents

The installed OpenCode skill documents the safe interfaces. With the shell running, use saturn data <command>; without it, use scripts/workspace_api.py. Agents should never hand-edit workspace.json, and should use real ids obtained from a list command. The graph is a separate, additive way to record context — it never changes note or task content.
